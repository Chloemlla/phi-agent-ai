# 0016. 生图使用独立配置与端口，模型由用户选择

- 状态：已接受（2026-11-22；实现未开始）
- 日期：2026-11-22
- 决策者：Sukirya

## 背景

生图与聊天模型的差异很大：协议不同、端点不同、凭据可能不同、输出是资产而不是文本；前沿图片模型（GPT-Image-2.5 Flare / Sunburst、GPT-Image-2.6、Nano Banana 2.1）在分辨率、编辑、参考图、GIF / SVG 等能力上差异明显。

用户明确要求：**生图单独配置；模型由用户选择，不由 Agent 选择；Agent 主动调用**。把生图塞进 `providers.json` 或 `auxiliary.json` 会让文本模型配置变复杂，也容易让 Agent 在运行时“猜”该用哪个图片模型。

## 决定

- 生图使用独立配置 `<data-dir>/image.json`：provider、`baseUrl`、凭据引用、**用户选择的模型**、默认尺寸 / 质量 / 格式、每 Turn 上限、外发授权。不复用聊天 provider 的配置。
- 增加可选的 `image.generate` 端口与适配器；首批建议 `openai_images` 与 `gemini_images`，其他协议由插件提供。模型目录记录能力（4K、蒙版编辑、参考图、GIF、SVG、速度档位），不硬编码未公开的分辨率。
- **模型由用户在设置中选择，Agent 不能选择或切换**：`image_generate` 工具没有 `model` 参数，运行时注入配置中的模型。Agent 只决定何时生成、提示词是什么；不决定用哪个模型。
- **Agent 主动调用**：`image_generate` 是工具，不是后台任务。默认只暴露给 Lead，是否给 Sidekick 由配置决定；没有“系统自动生图”。
- 未配置、未启用或缺少外发授权时，工具不存在或明确报错；不回退到聊天模型。
- 生成结果进入内容寻址的本地资产库，记录来源模型、提示词摘要和尺寸；不热链远程 URL，不把 base64 塞进模型上下文。
- 格式安全：PNG / JPEG / WebP / GIF 可作为消息附件渲染；**SVG 只允许下载，不内联渲染**（脚本 / 外链风险）。校验 magic bytes、MIME、尺寸、文件大小；剥离 EXIF。
- 参考图只能是用户提供的本地资产；不允许 Agent 传入任意 URL。每 Turn 默认最多 4 张。
- headless 提供配置、生成、列出、删除命令；测试用脚本化 image provider。

## 取舍

- **独立配置而不是复用聊天 provider**：设置更碎，但允许图片和聊天使用不同厂商、不同 Key、不同端点，边界清楚。
- **用户选模型而不是 Agent 路由**：可预测、成本可控、不会在运行中猜；代价是用户要为任务手动切换模型，Agent 不能按场景自动选。
- **一个活动模型而不是多模型池**：第一版简单；需要多后端并行时再扩展。
- **SVG 只下载不内联**：牺牲消息内直接预览矢量图；换来不把模型生成的 SVG 注入 DOM 的安全边界。
- **工具调用而不是后台任务**：符合“Agent 主动调用”；代价是生图会阻塞当前步骤直到返回（可设置超时）。

## 后果

- 新增 `image.json`、设置页「生图」区域、`image.generate` 端口、`assets/image-model-catalog.json`、资产库与清理逻辑。
- `ContentBlock` / tool result 需要支持图片附件引用；UI 在消息流渲染图片、支持下载；SVG 显示下载卡片。
- 事件：`ImageConfigured` / `ImageGenerated` / `ImageDeleted`；用量按模型 / 会话记录。
- 外发授权按图片 provider 记录；提示词与生成结果都按不可信内容处理。
- 测试：模型固定、MIME / 尺寸校验、SVG 不内联、GIF 限制、无授权时工具不存在、资产清理。
- 何时重新审视：需要多图片后端、Agent 自动选模型、或需要图片编辑 / 参考图工作流时。
