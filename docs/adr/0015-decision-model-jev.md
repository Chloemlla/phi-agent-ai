# 0015. 决策模型作为有界判断层（Jev），而不是文本生成器

- 状态：已接受（2026-11-22；实现未开始）
- 日期：2026-11-22
- 决策者：Sukirya

## 背景

Agent 里有很多「判断」点：这次命令要不要弹审批、长工具输出要不要压缩、循环是否该结束、用户消息该路由到哪。当前做法要么是硬编码规则，要么让聊天模型输出 JSON 再解析——后者脆弱、贵，而且概率不可校准。

Jev（TypeSafe）提供了另一种形态：不生成文本，接收一段 `state` 和若干**类型化问题**（`noul` 二元、`choice` 封闭选项、`score` 有序量表），直接返回带校准概率的结构化判定。它可以显著降低「让 LLM 输出 JSON 再提取」的脆弱性，也适合减轻审批弹窗负担。用户要求以 BYOK 方式接入，端点由用户填写。

## 决定

- 增加可选的 `decision.evaluate` 端口与 `jev_decisions` 协议；独立配置 `<data-dir>/decision.json`：`baseUrl`（用户填写）、凭据引用、模型 id（如 `typesafe/jev-latest` 或固定版本）、超时。
- 请求只包含 `state` 与类型化问题；响应只包含概率 / 置信度 / 得分与用量，**没有自然语言文本**。不支持多轮对话，上下文由调用方拼进 `state`。
- 按决策点配置，而不是全局一个阈值：第一版支持 `approval_triage`（审批分流）与 `tool_output_compaction`（长工具输出处理）；后续可加 `loop_completion` / `route`。每个决策点可单独启用、设阈值、限定作用域。
- **决策模型只是判断层，不是编排器**：不跑工具循环、不生成回复、不拥有权限。它可以回答「这个动作是否属于用户已授权的低风险类别」，但不能扩大权限。
- **审批分流**：策略仍拥有最终权威。只有用户显式启用「智能审批」并授权某类低风险动作时，决策模型才能在置信度达到阈值时把 `Ask` 变成自动放行；高风险 / 不可逆 / 未知风险**永远走人**；低置信度、超时、错误、schema 不合法一律回到人。每次自动放行都记录模型、问题、概率、阈值、理由与动作摘要，用户可查看和撤销。
- **长工具输出**：决策模型选择处理策略（`keep_full` / `summarize` / `head_tail` / `reference_only`）；真正的摘要由文本 `summarizer` 角色或确定性截断完成，Jev 不负责生成文字。完整输出始终保留在 Blob，模型上下文只拿压缩后的版本。
- 失败安全：审批分流失败 → 询问人；压缩失败 → 确定性 head/tail；**绝不**在失败时自动放行，也不静默切换到聊天模型。
- 外发前对 `state` 做 secret 脱敏；决策内容需要单独的 `EgressGrant`。事件：`DecisionRequested` / `DecisionReturned` / `DecisionFailed` / `DecisionAutoApproved` / `ToolOutputCompacted`。
- headless 与桌面都要有配置、测试和审计入口；测试用脚本化 decision provider，不依赖真实 Jev。

## 取舍

- **类型化决策而不是让聊天模型输出 JSON**：输出可校准、代码可直接消费、输入成本低；代价是只能问封闭问题，不能做开放式推理。
- **自动放行而不是全部人工**：减轻审批疲劳；风险是误放行。缓解方式是只允许用户预授权的低风险类别、阈值本地校准、高风险永远人工、全过程审计。
- **独立协议而不是复用聊天网关**：决策 API 的请求 / 响应形态与聊天不同；代价是多一个适配器、一个端口和一份配置。
- **本地校准阈值而不是抄 0.8/0.9**：不同动作、不同风险等级的分布不同；代价是上线前需要样例评估，不能开箱即用。

## 后果

- `phi-contracts` 增加 `DecisionPort`、`DecisionRequest/Response`、`DecisionQuestion`、`SLOT_DECISION_EVALUATE`；`decision.json` 与设置页「决策模型」区域。
- `policy.evaluate` 的 `Ask` 分支可以调用 `approval_triage`；审批卡显示「自动放行 / 人工」及决策详情。
- 工具结果进入上下文前可以调用 `tool_output_compaction`；`summarizer` 后续实现前先用确定性截断。
- 用量记 `inputTokens`（输出 token 通常为 0）；不引入预算硬上限。
- UI 增加：决策模型配置、阈值、启用的决策点、自动放行历史、一键撤销；审批卡可展开查看概率。
- 测试：无配置 / 超时 / 低置信度 / 高风险 → 人工；自动放行有审计；压缩保留完整 Blob；schema 不合法拒绝。
- 何时重新审视：需要多步推理、开放式判断，或 Jev 协议不可用时；不要用聊天模型假装决策模型。
