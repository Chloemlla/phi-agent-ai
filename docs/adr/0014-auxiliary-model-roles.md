# 0014. 辅助模型按角色绑定，作为服务调用而不是 Agent

- 状态：已接受（2026-11-22；实现未开始）
- 日期：2026-11-22
- 决策者：Sukirya

## 背景

`40-runtime/model-gateway.md` §8 已经定义「辅助模型不是 Agent」：它不跑行动循环、不调工具、无记忆，是一个受约束的调用。但代码里没有角色绑定，也没有统一的调用路径。接下来需要支持的不只是审批判定，还包括：

- 会话标题生成；
- 记忆的后台整理（合并、拆分、纠正、更新概述）；
- 生图；
- 以及后续可能出现的摘要、嵌入、路由选择等。

如果每个功能都自己读配置、自己打 provider API，设置、外发授权、用量和审计会散落各处；如果把它们做成 Run 或 Agent，又会污染 Turn / Run 语义，并引出「辅助模型审批又要先审批」的递归问题。

## 决定

- 定义一组**文本辅助模型角色**，按角色绑定 provider + model + thinking：`session_title`、`memory_maintenance`、`approval_judge`（后续）、`summarizer` / `embedding`（后续）。角色注册表可扩展，但每个角色必须有明确的能力要求和输出契约。
- **生图不走这套文本角色配置**：它有独立的 `image.json`、`image.generate` 端口和资产库；模型由用户在设置中选择，Agent 只能主动调用工具，不能选择或切换模型（ADR-0016）。
- **决策模型也不走文本角色**：它是独立的 `decision.evaluate` 端口与 Jev 协议，接收状态和类型化问题，返回概率/置信度，不生成文本（ADR-0015）。
- 角色绑定是**应用级设置**，保存在独立配置中（建议 `<data-dir>/auxiliary.json`）；第一版不做每会话覆盖。未绑定或能力不匹配时，对应功能**明确禁用并说明原因**，不静默回退到 Lead 或别的模型。
- 辅助调用 / 辅助任务是**服务调用**：不创建 Turn、Run、Step、AgentInstance，不进入执行树，不跑工具循环，不注入完整会话历史。它们发布带 `callClass=auxiliary` 的审计与用量事件，可携带 `sessionId` / `matterId` 做归属，但永远不产生 `TurnStarted` / `RunScheduled` / `StepStarted`。
- 辅助任务由插件或节点后台任务编排，有超时、可取消、必要的单飞约束：每个会话最多一个标题任务，每个数据目录最多一个记忆整理任务。
- 结构化输出按角色约束：标题是一行短文本；记忆整理是受限 JSON 提案；生图是资产引用。所有模型输出都视为不可信输入。
- 记忆整理的提案必须再过一遍记忆准入屏障和 owner 级管理操作；`forget` 永远不由后台自动执行。生图落到本地资产库，只接受 PNG / JPEG / WebP，不热链远程 URL。
- **外发授权**按角色和内容类别分别授予：标题需要会话文本，记忆整理需要记忆事实；生图与决策模型分别由 ADR-0016 / ADR-0015 规定。没有对应 `EgressGrant` 时功能禁用；本地 provider 也要显式绑定。
- 文本辅助角色走现有模型网关；生图与决策模型使用各自的独立端口，不复用聊天协议。
- 每个角色都必须有 headless 入口与事件，测试不依赖桌面 UI。

## 取舍

- **按角色绑定而不是自动路由**：选择可预测、可审计、没有隐藏换模型；代价是用户要手动配置。以后需要自动选择时，可以加一个 `router` 角色或 `strategy.modelRouter`，但默认仍然是显式绑定。
- **服务调用而不是 Agent**：避免标题 / 记忆整理污染 Run 树，也避免审批递归；代价是这些任务不能自由使用工具。如果某个任务确实需要工具，它应该被派发成一个 Sidekick，而不是伪装成辅助调用。
- **标题自动生成而不是手工**：体验更好；风险是标题不准。缓解方式是只在标题仍为默认值时自动应用，用户改名后不再覆盖，且随时可改。
- **后台整理记忆而不是只在写入时判断**：可以合并重复、纠正过时事实；风险是模型改错。缓解方式是提案 + 审计 + 危险操作（纠正 / 失效 / 忘记）进入待确认，`forget` 不自动。
- **生图与决策模型单独成面**：它们分别需要不同的协议、配置和安全策略；硬塞进 `auxiliary.json` 会让文本角色配置变得混乱。代价是设置页多两个区域、多两个适配器。

## 后果

- `ModelSpec` 增加 `capabilities`（`chat` / `tools` / `vision` / `image_generation` / `embedding`），设置页按能力过滤；已有模型默认具备 `chat` + `tools`。
- `ModelRequest` 增加 `callClass` / `purpose`，`runId` 改为可选；文本辅助调用走 `auxiliary` 受限路径。
- 新增 `auxiliary.json`、设置页「辅助模型」区、headless `roles` 命令；生图与决策模型分别使用 `image.json` / `decision.json`（ADR-0016 / ADR-0015）。
- 新增后台任务：首个助手回复后的标题任务；记忆写入阈值 / 空闲 / 显式命令触发的整理任务。
- UI 增加：背景用量（按角色 / 会话 / 天）、会话标题来源、记忆整理历史；图片与决策结果各自在独立区域展示。
- 测试：headless 脚本化 provider 覆盖标题、记忆提案；验证这些调用不产生 Turn / Run；验证无外发授权时功能禁用。
- 何时重新审视：需要自动路由、辅助任务需要工具、或需要按会话覆盖角色绑定时。
